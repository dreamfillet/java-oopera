# java-oopera
Техническое задание проекта №4
Представьте, что вы устали от освоения тонкостей ООП и решили немного отдохнуть, и сходить в городской театр на новую оперную постановку. После представления ваш друг, который никогда не был в опере, спросил вас, насколько это похоже на обычный театральный спектакль. 
И в этот момент вы поняли, насколько хорошо театральный мир соответствует концепции ООП. Ведь опера — это тоже представление, но со своими особенностями — проходит под музыку и вместо речи актёры поют. Самое настоящее наследование, которое вы изучали всю неделю! Подумав, вы решили смоделировать работу театра в терминах ООП и для этого разработать небольшое приложение, которое помогло бы руководству в управлении работой театра.
Определяем основные классы
Первое, что нужно сделать при разработке любого ООП-приложения, — это определиться, какие основные сущности (классы) будут в приложении. Предлагаем вам подумать, какие классы вы бы выделили в приложении, описывающем работу театра.
Итак, в качестве классов будем использовать общие сущности: спектакль (Show), актёр (Actor) и режиссёр (Director). А отдельные их экземпляры, например, конкретный спектакль, будут объектами этих классов.
Теперь давайте определимся с признаками сущностей, которые будут полями в наших классах. У спектакля нас будут интересовать такие признаки, как название (title), длительность в минутах (duration), режиссёр (director) и список актёров (listOfActors). Для актёра добавим поля имя (name), фамилия (surname), пол (gender) и рост (height), а для режиссёра имя, фамилия, пол и количество поставленных спектаклей (numberOfShows).
Создайте классы Show, Actor и Director. Для каждого из этих классов добавьте соответствующие поля и конструкторы.
Добавляем наследование
Когда вы создавали классы, вы могли заметить, что часть полей у актёра и режиссёра дублируются — это имя, фамилия и пол. Всё потому, что и актёры, и режиссёры являются людьми, а эти признаки характерны для всех людей. То есть, в терминах ООП, существует базовый класс Person («Человек») с двумя наследниками — актёр и режиссёр. Давайте отразим это в структуре классов. Добавьте класс Person и перенесите поля, которые относятся к любому человеку, в этот класс. 
Теперь давайте подумаем про разные типы спектаклей. Представьте, что ваш театр достаточно большой и в нём проходят самые разные спектакли: классические пьесы, балетные и оперные постановки. Конечно, у балета и оперы есть свои особенности. Например, и то и то обязательно проходит под музыку, а значит, есть автор музыки. 
Кроме того, у балета и оперы есть либретто — описание постановки в виде текста. У балета, кроме того, есть хореограф, а у оперы — хор, который состоит из определённого количества человек. Давайте подумаем, как отразить разные виды спектаклей в приложении.
Итак, для нашей задачи будет логично создать класс для всех музыкальных постановок — MusicalShow, а классы Ballet (балет) и Opera (опера) сделать наследниками этого класса.
Доработайте иерархию классов с учётом новых классов. В MusicalShow добавьте поля musicAuthor (автор музыки) и librettoText (текст либретто). Класс Ballet также должен содержать поле choreographer (хореограф), а класс Opera — choirSize (количество человек в хоре). Добавьте для новых классов конструкторы, содержащие все поля.
Оживляем классы
Пока наши классы для сотрудников театра и театральных постановок просто статически хранят информацию. Пришло время добавить им некоторое поведение. Вам нужно реализовать следующие возможности:
Распечатать текст либретто.
Распечатать информацию о режиссёре спектакля — должны выводиться его имя и фамилия.
Распечатать список всех актёров, участвующих в спектакле. Для каждого актёра при этом должны выводиться имя и фамилия, а также в скобках его рост.
Добавить нового актёра в спектакль. При добавлении актёра должна быть проверка, нет ли уже такого актёра среди добавленных. Если есть, должно выводиться предупреждающее сообщение, и актёр не должен добавляться. Актёры считаются одинаковыми, если у них совпадают имя, фамилия и рост.
Заменить одного актёра в спектакле на другого (на вход подаётся объект нового актёра и фамилия того, которого он заменяет). Если актёр с такой фамилией отсутствует, должно выводиться предупреждающее сообщение. Порядок актёров в списке значения не имеет.
Подумайте, какие методы для этого нужно добавить в какой из классов.
Вы можете проверить себя с помощью нашей подсказки:
Подсказка

Распечатать текст либретто. Так как либретто есть у любого музыкального спектакля, будет логично добавить этот метод в класс MusicalShow . Метод должен выводить на экран содержимое поля librettoText .
Распечатать информацию о режиссёре спектакля. Нам нужно описание объекта класса в виде строки, поэтому есть смысл переопределить для этого метод toString
Распечатать список всех актеров, участвующих в спектакле. Список актёров есть у любого спектакля - поэтому поместим метод в класс Show. Он будет проходить по списку listOfActors и выводить его содержимое на экран. Для вывода имени, фамилии и роста также обдумайте использование метода toString
Добавить нового актера в спектакль. Метод должен добавлять актёра в список listOfActors. Чтобы сравнивать актёров между собой, вам понадобится реализовать в классе актёра метод equals. Не забудьте, что при реализации метода equals обязательно также реализовать и hashCode
Заменить одного актёра в спектакле на другого. Здесь могут быть разные варианты реализации. Можно найти актёра для замены, удалить его из списка с помощью метода remove класса ArrayList, а затем добавить нового в конец списка. А можно сразу обновить актёра на том же месте, используя метод set
Начинаем представление
Осталось совсем немного — собрать всё вместе и позволить нашему театру начать работу. Для этого создайте класс Theatre с методом main.
Внутри метода main вам нужно выполнить следующие действия:
Создать трёх актеров и двух режиссёров. Также создайте одного автора музыки и одного хореографа
Создать три спектакля: обычный, оперный и балет
Распределить актёров по спектаклям. Используйте для этого метод добавления нового актёра в спектакль. Один актёр может участвовать в нескольких спектаклях.
Для каждого спектакля выведите на экран список актёров.
Замените актёра в одном из спектаклей на актёра из другого спектакля и ещё раз выведите для него список актёров.
Попробуйте заменить в другом спектакле несуществующего актёра
Для оперного и балетного спектакля выведите на экран текст либретто.
